`/api/health`는 공개 생존 확인만 제공한다. DB·queue·제공자 구성은 플랫폼 관리자 전용 `/api/internal/readiness`에서 확인한다. 키 존재는 실제 제공자 검증 성공을 뜻하지 않는다.

`EDUON_DEPLOYMENT=production`은 현재 승인되지 않은 운영 시작을 차단한다. 이 버전의 `releaseConfiguration`은 staging-evidence를 항상 unverified로 두며 canRelease=false다. 실제 관문 증거와 별도 릴리스 변경 검토 후 이 잠금을 갱신한다. 실제 운영 빌드에 production 플래그를 넣은 로컬 3110 검사에서 instrumentation이 RELEASE_GATES_NOT_MET로 실패했고 `/api/health`, `/classes`, `/api/learning/readiness` 요청이 모두 500이었다. 프로세스는 포트를 바인딩했으나 기능 요청은 차단됐다. 검사 후 프로세스를 종료했다. 일반 로컬 preview의 `next start` 성공은 운영 관문 통과가 아니다.

배포 전 소유자가 위 증거·비용·대상 URL을 검토하고 배포를 지시해야 한다. 초기 관찰은 원장 3명·학부모 3명에게 합성 시나리오로 제안한다. 자동 모집·연락은 하지 않았다.
