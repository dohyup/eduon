# P2 인증·보호자·권한 결정 기록

2026-11-09 사용자 선택: **Supabase Auth + PostgreSQL**, 기존 프로젝트 연결 정보는 사용자가 `.env.local`에 설정.

## 인증

- 이메일 보안 링크 + PKCE. 자체 비밀번호 저장 없음.
- `@supabase/ssr` 0.12.7 / `@supabase/supabase-js` 2.119.0 고정. 서버의 `getUser()`로 신원을 재확인하고 DB의 비활성·소속·권한을 매 요청 검사한다.
- `getSession()`의 사용자 객체나 `user_metadata`로 운영자·원장·보호자 권한을 부여하지 않는다.
- 서버 전용 HttpOnly/SameSite=Lax 쿠키, 운영 Secure 쿠키. Proxy가 갱신 쿠키를 요청·응답에 함께 반영한다.
- 인증 fetch는 5초 제한, DB 연결 5초·SQL 10초 제한. 인증 장애 시 권한을 허용하지 않는다.
- 변경 API는 정확한 APP_ORIGIN·JSON·32KiB 본문·공유 DB 레이트리밋을 검사한다. 세션·프로필 응답은 private/no-store.
- 앱은 요청 시 렌더링해 빌드 시점의 인증 준비 상태나 수업 목록을 계속 제공하지 않는다.

## 가입·보호자

- 일반 신규 가입은 기본 비활성. `AUTH_ALLOW_SIGNUP=true` 및 `PRIVACY_POLICY_VERSION`이 함께 있어야 신규 인증 계정 생성을 허용한다.
- 초기 계정은 기존 Supabase 계정 또는 운영자가 대시보드에서 초대한다. 연령·동의·개인정보 정책 확정 전 실제 미성년자 정보를 수집하지 않는다.
- 이메일 확인과 보호자 확인은 별도다. 운영자는 실제 확인 후 계정 ID·10~500자 사유를 기록한다. 이것은 자동 본인확인이나 법적 보호자 자격 인증이 아니다.
- 확인된 보호자는 자신의 새로운 자녀 프로필을 만들 수 있다. 이미 존재하는 학생을 이름/이메일 검색만으로 가져올 수 없다. 기존 타 계정 학생 연결은 자동 구현하지 않았다.
- 학생 초대는 수신 이메일에 묶인 24시간·32바이트 난수·해시 저장·한 번 소비 토큰. 부모 자신의 계정으로 수락하거나 다른 이메일로 수락할 수 없다.
- 초대 원문은 DB/감사 로그에 저장하지 않는다. 링크의 fragment에 넣어 서버 URL·Referer 로그에 토큰이 남지 않게 했다. 재발급·폐기·보호자 관계 해제·발급자 비활성·동시 수락을 검사한다.

## 학원·강사

- 원장은 학원별 소속, 강사는 수락한 소속 + 담당 수업으로 권한을 제한한다.
- 입점 신청/반려/재신청/승인/정지는 허용된 상태 전이와 감사 기록을 남긴다. 승인 전 공개 불가.
- 강사 초대도 이메일 바인딩·해시·만료·원자적 소비·발급자의 현재 원장 소속을 검사한다. 해임된 발급자의 토큰은 사용할 수 없다.
- 수업 공개는 학원 잠금·정렬된 강사 잠금 후 소속·기간·회차·동시간대 충돌을 재검증한다. 잠금 안에서 외부 인증/메일 호출을 하지 않는다.
- P3가 첫 결제 시 purchaseLockedAt을 설정하는 계약을 마련했다. 잠금된 수업의 가격·시간 변경을 막고 메타데이터 변경에서도 회차 ID를 보존한다. 실제 결제는 아직 없다.

## 메일·서비스 추천

인증/DB는 Supabase, 메일은 **Resend 커스텀 SMTP + 초대 API**를 추천한다. 메일 공급자는 아직 사용자 계약/키 설정을 확인하지 않았다. Resend 키·발신 도메인이 없으면 발송 성공으로 표시하지 않고 직접 전달 모드로 안내한다. 제공자 실패도 failed로 표시하며 재발급 경로를 유지한다. 테스트에서는 외부 메일 호출을 막는다.

참고: [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client?framework=nextjs), [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [Resend API](https://resend.com/docs/api-reference/emails/send-email).

## 아직 확인하지 않은 외부 상태

실제 Supabase 프로젝트에서의 로그인 메일·콜백·세션 갱신·로그아웃, 프로젝트별 DB 역할·풀러·SMTP와 실제 미성년자 운영 정책은 연결 후 확인해야 한다. 로컬 서명 테스트 세션과 합성 PostgreSQL 통합 테스트를 실제 Supabase 인증 성공으로 보고하지 않는다.
