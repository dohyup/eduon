# EDUON P2 구현·검증 결과

검증일: **2026-11-09 (Asia/Seoul)**. 작업 브랜치: `codex/eduon-mvp`.

상태: **P2 코드와 로컬 검증 완료. 실제 Supabase DB 연결·마이그레이션·이메일 로그인·새로고침 후 세션 유지·로그아웃 검증 완료.** 최신 외부 연결 결과와 남은 운영 검증은 [실제 Supabase 검증 기록](p2-supabase-verification.md)을 따른다. 아래 실행 결과와 미수행 항목은 초기 로컬 검증 당시의 기록이다.

## 사용자 결정

- Supabase Auth + PostgreSQL 사용.
- 기존 프로젝트가 있으며 사용자가 `.env.local`에 연결 정보를 설정한다.
- Resend 커스텀 SMTP/초대 API는 추천안이며 계약·발신 도메인·키 설정은 확인되지 않았다.

## 구현

| 영역 | 동작 |
| --- | --- |
| 인증 | Supabase 이메일 링크·PKCE·콜백·로그아웃·쿠키 갱신 어댑터. 서버 getUser 확인. 자체 암호 저장 없음 |
| 권한 | DB 사용자 활성 상태·학원 소속·담당 수업·보호자 관계를 서버 검사. 운영자 권한은 공개 가입으로 얻을 수 없음 |
| 자녀 | 확인된 보호자만 새 프로필 등록. 다른 학생 이름 검색으로 연결 불가 |
| 학생 초대 | 수신 이메일 바인딩·24시간·해시 저장·원자적 일회 소비·재발급/폐기·발급자/관계 재검증 |
| 학원 | 입점 신청·운영자 승인/반려/정지·수정 후 재신청·감사 기록 |
| 강사 | 수락된 학원 소속·발급자 현재 권한 검사·담당 강사 선택. 해임된 원장의 초대 무효 |
| 수업 | 과목·학년·수준·가격·정원·모집기간·회차·강사 검증. 학원 승인 전 공개 거부, 동시간대 충돌 방지 |
| 변경 보호 | P3 purchaseLockedAt 계약, 구매 고정 후 가격·회차 변경 거부 및 회차 ID 보존 |
| 공개 검색 | 실제 DB의 승인 학원·공개/모집 중·정원 가능 수업만 검색. 과목·학년·수준·예산·시간 필터, 커서 페이지 |
| 추천 | rules-v1 조건 기반 최대 5개, 근거·버전 기록. LLM이나 성적 향상 보장 없음 |
| 관리 목록 | 학원·수업 20개 페이지와 더 보기. 다음 페이지에도 소속 필터 유지 |
| 화면 | 실제 데이터 UI와 P1 합성 데모 명시적 분리. 미연결은 설정 필요 안내. 실패·대기·재시도·빈 결과 제공 |
| 메일 | 키 없음 manual, 제공자 오류 failed, 성공 sent 분리. 실메일은 보내지 않음 |

## 브라우저 검증 범위

- 미인증·위조 테스트 쿠키·외부 Origin 거부, 다른 학원의 목록/공개 접근 거부, 비운영자의 승인/보호자 확인 거부.
- 보호자 자녀 등록 → 초대 생성 → 다른 계정 거부 → 수신 학생 계정 연결.
- 원장 입점 → 운영자 승인 → 실제 DB 상태 확인.
- 원장 수업 개설 → 강사 배정 → 공개 → 공개 검색/상세에서 조회.
- 학부모·원장·운영자·강사·학생을 360/390/768/1024/1440px에서 검사. **로딩 종료와 실제 계정 데이터 표시를 기다린 후** 넘침·폼·목록을 확인했다.
- 390px의 5개 실제 데이터 역할 화면에서 axe WCAG A/AA·2.1 AA 위반 0. 수동 접근성 인증이나 실제 모바일 기기/Safari 검증은 아님.
- 390/1440px × 5개 역할, 최종 스크린샷 10장. 테스트 계정과 자료는 모두 합성이다.

## 검토에서 수정한 문제

- 구매 고정 수업 수정에서 동일 일정도 회차 ID를 새로 만들던 문제를 재현·수정.
- 발급자가 해임돼도 유효하던 강사 초대를 현재 원장 소속으로 재검증.
- 잘못된 커서의 UUID 캐스팅 오류와 존재하지 않는 날짜 정규화 문제를 엄격히 검증.
- 20개 이후의 관리 항목이 숨겨지는 문제를 서비스/API/UI 커서 페이지로 해결.
- 공개 검색은 요청당 최대 200개 DB 행, 추천은 최대 5페이지/100개 적격 후보로 제한. 빈 페이지라도 이어볼 커서를 제공한다. 전수 최적/정확도 보장은 하지 않는다.
- DB 조회만 있는 홈이 빌드 시점에 고정될 위험을 `connection()`으로 제거. 보호 페이지와 연결 상태도 빌드 결과에 고정하지 않음.
- Supabase 요청 5초, DB 연결/쿼리 제한 추가. 제공자 장애 시 접근 허용 금지.
- 변경 요청은 Origin·JSON·스트리밍 본문 상한·레이트리밋 검사.
- P1/P2 병렬 Playwright 실행의 artifact 파일 충돌을 서로 다른 출력 디렉터리로 분리.
- 테스트 서버는 Supabase/Resend 값을 비워 사용자 `.env.local`을 설정해도 실제 메일 발송이나 외부 인증에 섞이지 않게 함.

## 스킬 적용과 한계

superpowers 실행/TDD/완료 검증 절차와 gstack engineering/review/QA의 권한·신뢰 경계·상태·반응형 기준을 적용했다. 별도 작업자가 서비스·화면을 구현하고 읽기 전용 검토자가 인증/학원 격리/초대/캐시/목록/timeout을 검토했다. 부모 작업자가 발견 사항을 수정하고 실제 실행 결과를 확인했다.

gstack browse의 기존 실행 문제에 대해 Playwright 대체 경로를 유지했다. 정식 gstack 리뷰 로그의 CLEAR나 실제 Supabase 외부 연동 완료를 주장하지 않는다. 기존 커리업 삭제와 P1 작업을 보존했으며 커밋/푸시/병합은 하지 않았다.

## 실제 외부 연결을 기다리는 항목

마지막 안전한 설정 확인에서 DATABASE_URL, SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY는 미설정이었다. 값은 출력하지 않았다. 아래는 아직 수행하지 않은 일이다.

1. 기존 프로젝트 스키마/동명 테이블·백업·런타임 DB 역할 확인.
2. 해당 프로젝트에 초기 마이그레이션 적용과 RLS/연결 권한 확인.
3. 실제 이메일 링크 수신·PKCE 콜백·세션 갱신·로그아웃·계정 복구 검증.
4. 커스텀 SMTP/Resend 발신 도메인과 실메일 검증.
5. 가입 연령·동의·보호자 확인·보관/삭제 정책 확정. 일반 가입은 기본 비활성.

연결 방법은 [P2 설정 안내](p2-setup.md), 인증 결정은 [결정 기록](identity-decisions.md)를 따른다. 키를 설정하기 전 P2 전체 완료나 실제 인증 성공으로 표시하지 않는다.

## 남은 기술 사항

- 개발 도구 감사에서 low 1·moderate 8건, high/critical 0. 런타임 감사 0건. 강제 메이저 변경은 하지 않았으며 개발 도구 업데이트 시 재평가한다.
- PostgreSQL 테스트 실행기는 beta 태그의 Node 래퍼를 개발 의존성으로만 사용한다. 실제 엔진은 PostgreSQL 17이며 운영 DB/앱에 이 래퍼를 사용하지 않는다.
- Prisma/pg의 동시 query 관련 deprecation warning이 일부 테스트에 남는다. pg 버전을 고정했고 테스트는 통과했으며 향후 어댑터 업데이트 시 재확인한다.
- 공유 레이트리밋의 만료 행 정리는 운영 스케줄 정책에 포함해야 한다. 실제 클라우드 운영 설정은 외부 연결 후 확정한다.
