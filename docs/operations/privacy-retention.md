# 개인정보·보관 정책 검토 초안

**운영 정책으로 승인되지 않은 초안이다.** 보관 기간이나 법적 적합성이 확정된 것으로 표시하지 않는다. 운영 데이터 수집 전에 서비스 소유자와 정책 담당자가 범위·기간·동의 문구·공급자 계약을 확정해야 한다.

| 정보             | 목적·접근                             | 확정할 사항                                               |
| ---------------- | ------------------------------------- | --------------------------------------------------------- |
| 계정·자녀 연결   | 로그인·확인된 보호자/학생             | 미성년자 동의 절차, 연결 해제·계정 삭제                   |
| 주문·결제·정산   | 결제 사실·환불·감사                   | 판매/정산 주체, 필수 보관과 삭제 제한                     |
| 출결·수강권      | 담당 강사 기록, 본인/현재 보호자 열람 | 수업 종료 후 보관·정정 요청                               |
| 과제·답안·피드백 | 담당 강사·학생·현재 보호자            | 보관 기간, 파일 검사 위탁, 삭제 시 버전 이력 처리         |
| 후기·신고        | 완료 수강 후기와 운영 검토            | 공개 안내, 숨김·삭제·이의 신청                            |
| 전환 지표        | 학원별 집계, 관리자 전체              | 측정 동의/고지, actor ID 최소 보관·익명화                 |
| 화상             | 개별 입장·역할·시간 제어              | Daily 계약·데이터 처리 지역/위탁 고지·링크 전달 위험 수용 |

현재 접속 성공을 자동 출석으로 기록하지 않는다. 강사가 출석·지각·결석과 사유를 기록하고 수정 이력을 남긴다. 과제 재제출·피드백은 새 버전으로 보존한다. 참조 중인 제출 파일은 임의 삭제하지 않으며 미참조 파일만 감사 후 soft-delete한다. 일반 파일 삭제 API는 계정 탈퇴·개인정보 삭제 전체 정책의 구현이 아니다.

삭제 처리 운영안: 요청자 확인 → 보관 의무/분쟁 보존 여부 검토 → 대상 DB·객체·외부 제공자 목록 승인 → 제한된 작업으로 처리 → 최소 감사 기록 → 백업 보관 만료/복원 후 재삭제 목록 관리. 이 작업과 자동 만료 purge는 아직 구현하지 않았다. 무조건 cascade-delete나 감사 로그 전체 삭제를 운영 절차로 사용하지 않는다.

녹화는 기본 비활성이다. 추후 녹화를 추가하려면 별도 동의·접근·보관·삭제 설계를 먼저 승인한다. 생성형 학습 리포트는 P4 범위 밖이며 선택적 추천 설명에는 공개 수업 사실만 제공한다.

확정 후 PRIVACY_POLICY_VERSION·RETENTION_POLICY_VERSION·SELLER_POLICY_VERSION·REFUND_POLICY_VERSION·CONSENT_POLICY_VERSION을 설정하고 실제 문서/동의 UI/정책 스냅샷을 서로 대조한다. 임의 문자열을 넣어 정책 승인으로 대신하지 않는다.
