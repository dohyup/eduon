# P3 거래·결제 결정 기록

2026-11-09 (Asia/Seoul).

## 사용자 결정과 공급자 추천

사용자는 **공급자 선택 보류·내부 테스트만**을 선택했다. 실제 PG SDK·API 어댑터·계약·운영 키·과금·환불 요청을 외부 서비스에 연결하지 않는다. 원격 Supabase에는 P3 마이그레이션을 적용하지 않았으며, 거래 검증은 격리된 로컬 PostgreSQL과 테스트 인증 계정에서 수행한다.

추천은 **포트원 V2 + 토스페이먼츠 PG**다. 포트원 V2의 서명 검증 웹훅과 결제 조회·취소 계약을 활용하고, PG 추가 시 업무 로직을 유지하기 좋다. 단일 PG 연결의 단순함을 우선하면 토스페이먼츠 직접 연동도 후보이다. 이용료·PG 수수료·입점 학원의 판매자 지위·정산 계약은 확정하지 않았다.

근거: [포트원 V2 웹훅](https://developers.portone.io/opi/ko/integration/webhook/readme-v2), [포트원 V2 API](https://developers.portone.io/api/rest-v2), [토스페이먼츠 보안·멱등키](https://docs.tosspayments.com/reference/using-api/security-trust).

## 테스트 전용 정책

- 구매자는 운영자가 확인한 보호자이며, 취소되지 않은 자녀 연결이 필요하다. 한 주문은 한 자녀·한 모집기수다.
- 원화 정수 금액을 서버에서 계산한다. 학원 ID·수강 자녀·금액·정책·회차별 금액과 일정은 주문 스냅샷으로 보존한다.
- 판매자 식별은 해당 학원 ID다. 실제 판매자 책임과 플랫폼의 법적 지위는 계약 전에 별도 확정한다.
- 정책 버전은 `test-policy-v1`이다. 합성 수수료는 0으로 표시하며, 실제 0% 수수료 계약이나 특정 법적 환불 규정을 의미하지 않는다. 8%를 적용하지 않는다.
- 좌석은 최대 10분 보유하며, 모집 마감이나 첫 수업 시작이 더 빠르면 그 시각에 만료된다. 같은 학생·기수의 중복 신청을 차단하고 취소 이력이 있는 동일 기수 재구매는 별도 지원 전까지 거부한다.
- 0원 수업은 PG 결제 예약을 만들지 않는다. 무료 수강권 발급 절차는 별도 계약이 필요하며 이번 유료 수강 신청 범위에 포함하지 않는다.
- 회차별 금액은 총액을 정수로 나누고 나머지 원 단위를 앞 회차부터 배분한다. 테스트 환불은 아직 시작하지 않았고 이수되지 않은 선택 회차만 대상으로 한다.
- 환불 요청은 환불 완료가 아니다. 요청 중에는 대상 회차만 입장을 보류하고, 명확한 실패는 유효 접근을 복원한다. 성공 증거가 확인된 뒤에만 취소·재무 상태를 확정한다.
- 이미 지급한 거래의 환불은 과거 지급 기록을 수정하지 않고 조정 원장으로 남긴다. 이후 귀속액과 짝을 이루는 상계 기록으로 이월하고, 지급 가능액은 학원 전체 순잔액을 넘지 못한다.
- 자동 정산 송금은 구현 범위 밖이다. 운영자의 외부 지급 참조 등록은 실제 이체나 송금 성공 확인이 아니다.

## 경계와 활성화 조건

`PAYMENT_MODE=live`는 항상 비활성이다. 공급자 미설정이면 신청·결제 API가 차단된다. 가짜 결제 어댑터는 `PAYMENT_PROVIDER=fake`, 테스트 인증 제공자, 32자 이상 테스트 인증 키와 명시적인 테스트 실행 환경이 함께 있을 때만 허용된다. 운영 빌드와 실제 Supabase 인증 모드에서는 가짜 결제를 사용할 수 없다.

가짜 제공자의 메모리는 영속적인 외부 결제 기록이 아니다. 프로세스 재시작 후 공급자 기록을 잃은 상황을 실제 PG 복구 성공으로 보고하지 않는다. 주문·이벤트·환불·재처리 작업·원장은 PostgreSQL에 저장하며, 외부 조회가 불확실하면 예외 상태로 보존한다.

향후 실제 어댑터는 같은 환불 요청키의 멱등성을 유지해야 한다. PG의 멱등키 보존 기간을 넘겼거나 결과를 조회할 수 없으면 안전하지 않은 재요청 대신 `pending`을 반환해야 한다. 서버 재조회로 검증된 사실만 수강권을 바꿀 수 있고, 브라우저 리다이렉트의 상태·금액·결제 키는 성공 증거가 아니다.

실제 공급자 sandbox 연결, 웹훅 공개 수신 주소, 상점·학원 계약, 수수료·환불 정책, 스케줄러 배포·경보 발송, 운영 보관·삭제 정책은 별도 준비와 검증이 필요하다.
