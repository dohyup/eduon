# 이메일 숫자코드 로그인

2026-11-09. 실제 원장 브라우저 검증 도중 이메일 링크에서 `otp_expired`가 반복돼, 사용자가 숫자 인증코드 로그인을 선택했다. 링크가 이미 사용되거나 만료된 사실은 확인했지만 이메일 보안 스캔 등 구체적인 소모 원인은 확정하지 않았다.

## Supabase 설정

프로젝트의 Email Templates → Magic Link 본문을 코드 중심으로 설정한다. 링크를 함께 남기면 메일 미리 읽기에서 같은 토큰을 소비할 수 있으므로 이번 검증은 링크 없이 다음 본문을 사용한다.

```html
<h2>EDUON 로그인</h2>
<p>인증코드: {{ .Token }}</p>
<p>요청한 EDUON 로그인 화면에 직접 입력해 주세요.</p>
```

앱은 기존 `signInWithOtp` 메일 요청 경로와 Supabase의 `verifyOtp({ email, token, type: 'email' })`를 사용한다. `{{ .Token }}`을 넣는 설정과 코드 검증 계약은 [Supabase passwordless 가이드](https://supabase.com/docs/guides/auth/auth-email-passwordless), 링크 미리 읽기와 OTP 대안은 [메일 템플릿 문서](https://supabase.com/docs/guides/auth/auth-email-templates)를 확인했다. 실제 메일 템플릿 저장과 수신 여부는 사용자·실제 로그인 결과로 확인해야 한다.

## 앱 동작·경계

로그인 화면에서 이메일로 코드를 요청한 뒤 같은 화면에 숫자를 입력한다. 코드는 채팅에 보내지 않는다. 요청이 성공했다는 안내는 이메일 존재 여부나 실제 수신을 보장하지 않는다.

- `POST /api/auth/verify-otp`: 같은 Origin, JSON 본문 32KiB 제한, 엄격한 이메일·숫자 코드 입력 검사.
- 코드 검증은 이메일 SHA-256 기준 15분당 5회와 전역 분당 1,000회로 제한한다. 메일 요청은 기존 15분당 3회 제한을 유지한다.
- 제공자가 메일 발송 제한(429)을 반환하면 성공 안내 대신 RATE_LIMITED로 표시한다. 기본 Supabase 메일은 별도 공급자 한도가 있으므로 앱의 요청 제한과 구분한다.
- 실제 Supabase 제공자만 허용하며 데모·가짜 인증으로 성공 처리하지 않는다. 신규 가입 활성화 설정은 바꾸지 않는다.
- 세션·확인된 이메일·요청 이메일 일치를 검사하고 비활성 앱 계정은 거부한다. 불일치 세션은 해당 브라우저 범위에서 로그아웃한다.
- 기존 SSR HttpOnly·SameSite 쿠키를 사용한다. 응답은 `authenticated: true`만 반환하고 OTP·세션 토큰·제공자 오류 본문을 반환하거나 로그로 기록하지 않는다.
- 실패·완료 시 입력한 코드는 화면 상태에서 지운다. 성공하면 `/onboarding`으로 이동하고 실제 계정 권한을 다시 읽는다. 계정·원장·플랫폼 관리자 권한을 자동 부여하지 않는다.
- 오래된 링크의 콜백/fragment 오류는 고정 문구로 안내한다. 제공자 `error_description`이나 코드·토큰을 그대로 화면에 반영하지 않는다.

현재 로컬 HTTP 검증은 개발 서버를 사용한다. 운영 HTTPS의 Secure 쿠키 설정을 완화하지 않았다. 숫자코드는 Supabase의 실제 인증 수단이며 테스트 쿠키나 계정 가장을 대신하지 않는다.

## 현재 증거

새 단위 테스트에서 정상 제공자 세션 응답의 비밀 값 비노출, 외부 Origin·잘못된 코드·만료·비활성 계정·요청 제한·불일치/미확인 사용자 거부를 확인했다. 독립 소스 리뷰에서 구체적인 중요 결함은 발견되지 않았다. 제공자 응답을 모의한 단위 테스트와 실제 이메일·브라우저 쿠키 유지 검증은 구분한다.

전체 단위 테스트 98개, 타입 검사, 린트와 분리된 `.next-p4` 디렉터리의 운영 빌드가 통과했다. 실제 사용자 로그인용 개발 서버는 `127.0.0.1:3000`에서 유지했다. 현재는 Supabase 메일 템플릿 저장 확인을 기다리는 단계다.

실제 원장 로그인·학원 신청·공개 수업 검증은 메일 템플릿 설정과 실제 코드 입력이 끝난 후 별도 결과로 기록한다. 사용자는 검증용 학원 한 곳만 DB에서 승인하는 것을 허용했으며 플랫폼 관리자 권한 부여는 허용 범위에 포함하지 않았다.
